## [0.1.9] - 2026-05-27

### Added
- **Auto-fixup based on policy findings.**
  - `Finding` now carries an optional `fix` shell command.
  - `conventional_commits` and `no_wip_commits` policies generate
    `git commit --amend -m "…"` fixes automatically.
  - New `giton/store.py` persists findings to `.giton/last_check.json`
    after every `policy check` and hook run.
  - New `giton/fixups.py` with `apply_fix` / `apply_all` helpers; honours
    `GITON_NON_INTERACTIVE` via existing `interactive.confirm`.
  - New CLI command: `giton policy fix [--yes]` — applies available fixes
    from the most recent check.
  - Shell REPL gained `policy fix` command.
  - `tests/test_fixups.py` (6 cases): fix generation, store roundtrip,
    command execution, real-repo amend.

## [0.1.8] - 2026-05-27

### Fixed
- Catalog default plugin commands now match the actual CLIs of the
  packages they install:
  - `pyqual`: `pyqual check {paths}` → `pyqual gates --workdir {root}`
  - `vallm`: `vallm check --diff {diff_file}` → `vallm batch {paths}`
  - `pretest`: `pretest run` → `pretest scan`

### Added
- `tests/test_plugin_runner.py` (8 cases) using a fake executable plugin
  to lock in placeholder expansion, exit-code propagation, disabled
  skip, missing-binary handling (127), and multi-plugin ordering.
- `examples/plugins/` worked example: registers a custom shell-script
  plugin in an isolated repo, runs `pre-commit`, asserts placeholders
  expanded and output captured.

## [0.1.4] - 2026-05-27

### Added
- `commit-msg` hook — validates the message file before the commit
  finalises; aborts with a tip when policies fail.
- `giton fixup [--target SHA] [--yes]` — creates a `fixup!` commit
  from staged changes with a backup ref under
  `refs/giton/backup/fixup-<timestamp>`.
- `giton history log` / `history clean` — safe autosquash with backup
  ref (`refs/giton/backup/clean-<timestamp>`), headless by default.
- `giton/history.py` primitives: `head_sha`, `make_backup_ref`,
  `list_log`, `upstream_range`, `create_fixup`, `has_staged_changes`,
  `autosquash`.
- `tests/test_history.py` (8 cases): hook installation, backup refs,
  fixup + autosquash, CLI fixup, commit-msg hook.

### Changed
- `conventional_commits` and `no_wip_commits` policies now also fire
  on the `commit-msg` trigger.
- `repo_config` defaults gained `commit-msg` with `fail_on_policy: true`.

## [0.1.3] - 2026-05-27

### Added
- Built-in policy engine (`giton/policies.py`): `conventional_commits`,
  `no_wip_commits`, `no_secrets`, `max_file_size`.
- Per-repo config `.giton/config.yaml` with deep-merge defaults
  (`giton/repo_config.py`).
- `giton policy {check,init,list}` CLI sub-app.
- `giton/interactive.py` — `confirm` / `choose` with TTY detection.
- `runner.run_trigger` returns `TriggerOutcome` (findings + results).
- `tests/test_policies.py`.

### Changed
- Hooks now evaluate built-in policies; `post-commit` is advisory.
- Shell REPL gained `policy` commands.
